CODE SHARING APP — BEGINNER SETUP AND RUNNING GUIDE

This guide explains how to set up and run the Code Sharing App on
Windows.

PROJECT COMPONENTS

Python runs the backend. FastAPI provides the backend API. PostgreSQL
stores users, questions, and votes. Docker Desktop runs PostgreSQL in a
container. HTML, CSS, and JavaScript make up the frontend. Git and
GitHub store and synchronize project files.

IMPORTANT SAFETY RULES

-   Run commands from the project folder unless stated otherwise.
-   Never commit .venv/ or pycache/.
-   Leave the untracked file named “commands” alone unless the team
    confirms it belongs in Git.
-   Do not import database-data.sql into a database that already has
    records. It contains fixed development IDs and can conflict with
    existing data.
-   Local database credentials are for development only, not production.
-   Do not delete containers or run DROP/TRUNCATE SQL commands as a
    troubleshooting shortcut.
-   The test account named testuser has a placeholder password hash and
    may not be able to log in.

1. INSTALL THE REQUIRED TOOLS

Git: 1. Install Git for Windows from https://git-scm.com/download/win 2.
Open PowerShell and run: git –version

Python: 1. Install Python and ensure it is available in PATH. 2. Check
it in PowerShell: python –version

Docker Desktop: 1. Install from
https://www.docker.com/products/docker-desktop/ 2. Start Docker Desktop
and wait for the engine to be ready. 3. Check: docker –version docker ps
-a

If Docker says it cannot start, open Docker Desktop and wait for it to
finish starting before retrying.

2. DOWNLOAD THE PROJECT

Choose a folder for coding projects, then run these commands. Example:

cd “$HOME” git clone
https://github.com/Chyreee/Opdracht-3-OpenICT-Cyberlapers.git cd
“Opdracht-3-OpenICT-Cyberlapers”

Switch to the integration branch and update it:

git switch Homescreen git pull origin Homescreen

If the local Homescreen branch does not exist, use:

git switch -c Homescreen –track origin/Homescreen

Check the branch:

git branch –show-current

It should say Homescreen. Check files with:

Get-ChildItem

Important files: - main.py: backend - requirements.txt: Python
dependencies - setup.ps1: setup script - login.html, login.js,
login.css: login page - homescreen.html, homescreen.js, style.css:
feed - database/schema.sql: database table definitions -
database-data.sql: development test data export

If any file listed above is missing in your current checkout, stop and
inspect the repository instead of guessing.

3. SET UP PYTHON

A virtual environment (.venv) keeps this project’s packages separate
from other Python projects.

From the project folder, check Python:

python –version

Run the setup script:

..ps1

If PowerShell blocks it, run:

powershell -ExecutionPolicy Bypass -File ..ps1

The script checks Python, creates .venv only if it does not exist,
installs the versions in requirements.txt, and checks dependencies with
pip check. It does not delete or recreate an existing .venv. However,
pip may install or change package versions if they do not match
requirements.txt.

Check dependencies manually:

..venv.exe -m pip check

Expected output:

No broken requirements found.

4. START AND CHECK POSTGRESQL

PostgreSQL is the database. Docker runs it in a container. This
project’s container is named codeshare-postgres and normally uses port
5432.

Check containers:

docker ps -a

If codeshare-postgres exists and is running, keep using it. If it exists
but is stopped, start it:

docker start codeshare-postgres

If it does not exist, create a new local development container:

docker run –name codeshare-postgres -e POSTGRES_USER=codeshare -e
POSTGRES_PASSWORD=codeshare_dev -e POSTGRES_DB=codeshare -p 5432:5432 -d
postgres:18

Then check:

docker ps

Do not create a second container if codeshare-postgres already exists.
If port 5432 is already in use, inspect existing containers and resolve
the conflict rather than deleting anything.

The local development connection settings are: Host: 127.0.0.1 Port:
5432 Database: codeshare User: codeshare Password: codeshare_dev

These are development credentials only. If main.py has different
settings in your checkout, use the settings in that file.

5. CHECK THE DATABASE SCHEMA

List tables:

docker exec codeshare-postgres psql -U codeshare -d codeshare -c “”

The expected tables are users, questions, and votes.

If these tables already exist, do not run the schema file again blindly.
If the database is genuinely fresh and empty and the tables are missing,
apply the schema:

cmd /c “docker exec -i codeshare-postgres psql -U codeshare -d codeshare
< database.sql”

Then list tables again:

docker exec codeshare-postgres psql -U codeshare -d codeshare -c “”

If you see errors that a table already exists, stop and inspect the
database. Do not use destructive SQL to force it through.

6. CHECK DATA BEFORE IMPORTING TEST DATA

Count the records. This command only reads data:

docker exec codeshare-postgres psql -U codeshare -d codeshare -c “SELECT
‘users’ AS table_name, COUNT() AS rows FROM users UNION ALL SELECT
‘questions’, COUNT() FROM questions UNION ALL SELECT ‘votes’, COUNT(*)
FROM votes;”

If you are setting up a fresh database, each count should be zero before
importing the development data.

The repository may contain database-data.sql. It contains test users,
questions, and votes. Only import it into an empty database with the
matching schema. Do not import it over existing records.

Check that the file exists:

Test-Path database-data.sql

If the file exists and all three tables are empty, import:

Get-Content database-data.sql | docker exec -i codeshare-postgres psql
-U codeshare -d codeshare

Read the output. If any SQL error appears, stop and investigate before
trying again.

Verify counts again:

docker exec codeshare-postgres psql -U codeshare -d codeshare -c “SELECT
‘users’ AS table_name, COUNT() AS rows FROM users UNION ALL SELECT
‘questions’, COUNT() FROM questions UNION ALL SELECT ‘votes’, COUNT(*)
FROM votes;”

The development export used during setup had 4 users, 14 questions, and
1 vote. The counts may change over time. The testuser account has a
placeholder password hash, so use a known working development account or
register a new one.

7. START THE BACKEND

Make sure Docker Desktop and codeshare-postgres are running. From the
project folder, run:

..venv.exe -m uvicorn main:app –reload

If .venv is active, this also works:

python -m uvicorn main:app –reload

Keep this PowerShell window open while using the app. The backend should
be available at:

http://127.0.0.1:8000

To stop it, press Ctrl+C in the terminal running Uvicorn.

8. OPEN AND TEST THE APP

Open the API documentation:

http://127.0.0.1:8000/docs

This page lists API endpoints and lets you test them.

Open login.html from the project folder in your browser, or use VS
Code’s Live Server extension if available. Live Server serves the
frontend locally and may avoid issues with opening an HTML file
directly.

Test the main workflow: 1. Open the login page. 2. Log in with a known
working development account, or register a new one. 3. Confirm you reach
the feed. 4. Create a question. 5. Confirm it appears in the feed.

If something fails, check the backend terminal, the browser console, and
http://127.0.0.1:8000/docs.

9. NORMAL DAILY WORKFLOW

Every time you want to work:

1.  Start Docker Desktop.
2.  Check the database container: docker ps
3.  If the existing container is stopped: docker start
    codeshare-postgres
4.  In PowerShell, go to the project folder.
5.  Check Git before pulling: git status
6.  If you have no local changes that need preserving, update the
    branch: git switch Homescreen git pull origin Homescreen
7.  Start the backend: ..venv.exe -m uvicorn main:app –reload
8.  Open login.html or your Live Server URL.
9.  When finished, stop Uvicorn with Ctrl+C. Optionally stop PostgreSQL:
    docker stop codeshare-postgres

Stopping a container does not normally delete its data. Removing a
container can lose data if it is not stored separately, so do not remove
it casually.

10. BASIC GIT WORKFLOW

Git tracks changes. GitHub stores the shared repository.

Check branch and status:

git branch –show-current git status

Review changes:

git diff

Stage only the files you intend to commit, for example:

git add main.py git diff –cached

Commit:

git commit -m “Describe the change”

Push the branch you are working on. For Homescreen:

git push origin Homescreen

Do not merge branches without agreeing on the plan with your team. Do
not blindly run git add . if unknown files are present. Never commit
.venv/, pycache/, local secrets, or the unreviewed file named commands.

The .gitignore file should include:

.venv/ pycache/ *.py[cod]

11. COMMON PROBLEMS

Docker Desktop cannot start: - Open Docker Desktop and wait for it to
finish starting. - Retry docker ps. - Do not remove containers as a
first step.

Container is stopped: - Run docker ps -a. - Start it with docker start
codeshare-postgres.

Port 5432 is already in use: - Inspect docker ps -a and check what is
using the port. - Do not delete another container without knowing what
data it holds.

Database does not exist or authentication fails: - Check the container,
database, user, password, port, and the settings in main.py. - Do not
reset or recreate the database without understanding the consequences.

ModuleNotFoundError: - Make sure you are in the project folder. - Run
..venv.exe -m pip check. - If necessary, run ..ps1.

Port 8000 is already in use: - Check other PowerShell windows for an
existing Uvicorn process. - Stop your own old process with Ctrl+C if
appropriate.

Git reports local changes: - Read git status carefully. - Do not use git
reset –hard or git clean as a shortcut. - Preserve your work before
switching branches or pulling.

12. USEFUL DATABASE COMMANDS

List tables:

docker exec codeshare-postgres psql -U codeshare -d codeshare -c “”

List users without showing password hashes:

docker exec codeshare-postgres psql -U codeshare -d codeshare -c “SELECT
id, username, created_at FROM users ORDER BY id;”

List questions:

docker exec codeshare-postgres psql -U codeshare -d codeshare -c “SELECT
id, title, author_id, study_year, beroepsrol, created_at FROM questions
ORDER BY id;”

Open an interactive SQL session:

docker exec -it codeshare-postgres psql -U codeshare -d codeshare

Inside psql: list tables sers show the users table structure exit

SQL statements such as SELECT end with a semicolon. SELECT reads data;
INSERT adds data; UPDATE changes data; DELETE removes data. Check a
WHERE clause carefully before changing or deleting records.
